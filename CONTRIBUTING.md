# Contributing

Pull Requests are welcome for original models, textures, interior integration, aiming-system code, improvements, and corrections for Project ViewPoint. Hiroki reviews every contribution and decides whether it becomes part of the mod. Repository acceptance does not guarantee a Steam Workshop release.

## Rights and permitted use

Models owned by Hiroki are All Rights Reserved and may be used only as part of the official Project ViewPoint mod, under [`LICENSE.md`](LICENSE.md). Do not reuse, sell, redistribute, or adapt those models for another mod, game, asset pack, or commercial product without prior written permission.

For a community contribution, the contributor keeps ownership and must explicitly grant Hiroki project-only permission to publish the editable source in this repository for review/collaboration, edit it, and include/distribute it as part of Project ViewPoint, including official mod releases on Steam Workshop. This permission does not allow standalone reuse or use in unrelated projects. Its exact terms must be stated in the Pull Request and recorded in [`ORIGIN-LICENSE.md`](ORIGIN-LICENSE.md). A Pull Request alone does not grant those rights. Contributions with unclear ownership or terms will not be accepted.

## Fork and review workflow

1. Create a fork of this repository in your own GitHub account. Your fork is separate from the official library.
2. Create a branch in your fork and make your proposed model, PNG, or code changes there.
3. Open a Pull Request from that branch to this repository's `main` branch. It appears in the **Pull requests** tab for review; opening it does not change the official files.
4. Wait for Hiroki to review the proposal, request adjustments, accept it, or decline it. Only Hiroki approves and merges changes into the official library.

Community contributors are not granted direct write access to the official repository. Do not push to its `main` branch or request write access as part of contributing. Downloading the official library continues to provide the maintainer's version until an approved proposal is merged.

## Before submitting files

1. Open an issue or discussion for substantial new models so the intended use can be reviewed first.
2. Submit only files you created or have clear written permission to contribute under the project-only terms above.
3. Do not submit Aseprite/Zprite project files, vanilla sprites, extracted Project Zomboid files, or third-party textures. You may submit a painted PNG based on a repository UV template. Describe vanilla visual references in text; do not attach or copy the referenced files.
4. Keep the editable source and only the dependencies needed to inspect it. Identify the authoring application and version when relevant.
5. Add the asset's creator, origin, dependencies, SHA-256, written permission, and status to `ORIGIN-LICENSE.md`.

## Pull Request details

Include what changed, where the model appears in the mod, the source paths, required dependencies, creator and origin, the exact project-only permission, and a preview when useful. Do not include game captures or extracted assets unless their use is clearly authorized.

## Review

Hiroki may request changes, decline a contribution, or accept it for the source repository without scheduling a mod update. Only Hiroki decides whether and when accepted work is incorporated into the mod and released on Steam Workshop.
